# Page types

Pick one type per URL from what page one shows for the query (dominant format and intent,
read and dated). Mixing types on one URL is a `NARROW SCOPE` signal.

| Type | Query shapes | Structure | Pitfalls |
|---|---|---|---|
| Head-to-head | "A vs B", "A or B" | Conditional verdict → decision table → attribute table → sections per difference → when to choose neither | A third product dominating page one; a one-sided verdict |
| Alternatives | "alternatives to X", "X competitors", "replace X" | Why people leave X (sourced: changelog, pricing page, forum threads with dates) → candidates by situation → migration notes | Bashing X; reasons to leave that are not sourced |
| Roundup | "best X for Y", "top X tools" | Inclusion criteria → short list with "best for" situations → attribute table → method and dates | Superlatives without checking the whole panel; unstated affiliate ties |
| Situation guide | "which X for {situation}", "X for small teams" | Questions that split readers → decision table or tree → products per branch | Branches invented without sources or reader evidence |
| Section on an existing page | Gate 0 = `NARROW SCOPE` via overlap | One comparison table + conditional verdict inside the existing page | Duplicating a separate comparison URL |

## Attributes to compare (start list, adapt per category)

Price and billing terms, free tier and its limits, plan limits, platforms and requirements,
integrations, data location or compliance claims (quote only, no interpretation), support
channels, notable features the query mentions. Every cell comes from `vendor-facts.csv`.

## Audit mode

Same type detection on the existing page; flag a type mismatch with today's page one as a
finding, not a rewrite order.

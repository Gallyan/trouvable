# Hour-budget rules

All numbers here are a **heuristic, design choice of this skill, to calibrate**.

## Budget

- Weekly hours `H` (`reported`, or 3 h `assumed`).
- Plannable share: **70 %** of `H` in the first 30 days, **80 %** afterwards. The rest absorbs
  surprises, reading results and learning.
- Period budget: 30 days ≈ 4 weeks → `0.7 × 4 × H`; 60 and 90 → `0.8 × 4 × H` each.
- Print the total planned hours per period next to the budget; never exceed it.

## Row rules

- One task per row, 0.5–6 h. Split larger tasks.
- Each row: week, task, hours (`estimated`), skill (or manual procedure), done-when check
  (observable: a file exists, a URL returns 200, a count is recorded).
- One main workstream at a time in the first 30 days; routine rows (weekly review) count too.
- Rows in days 61–90 may be conditional: "if checkpoint X shows Y, then…".

## Indicative effort (to calibrate)

| Task | Hours |
|---|---|
| Light audit reading and fix list (seo-audit) | 2–4 |
| First Search Console reading (seo-search-console) | 1–2 |
| Fix a template-level issue (title, canonical, noindex) — if the user can edit templates | 1–4 |
| Keyword verdict, one query | 0.5–1 |
| Brief for one page | 1–2 |
| Write one substantial page | 4–8 |
| Refresh one page | 1–3 |
| One directory / list submission | 0.5 |
| Weekly routine | 0.5–1 |

## Scale limit

More than about 3 people or more than a few thousand URLs: do not give hour tables. Plan by
workstream (owner, scope, sequence, checkpoint) and say why.
